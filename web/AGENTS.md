# web/AGENTS.md：LLM Wiki 瀏覽網站

> 本檔是「LLM Wiki 瀏覽網站」這個子專案的規格書與 AI 協作規則。
> 任何 AI agent 要修改 `web/` 或 `docs/` 之前，必須先讀完本檔；要修改 `wiki/` 內容時，則以根目錄的 [`AGENTS.md`](../AGENTS.md) 為準。
> 兩份文件分工：**根目錄 AGENTS.md 管「知識怎麼寫」，本檔管「知識怎麼呈現」。**

---

## 1. 專案目的

`wiki/` 裡的 Markdown 是給 AI 維護的知識庫。檔案一多，直接在資料夾裡點開 `.md` 很難閱讀：`[[雙括號連結]]` 不能點，看不到哪些頁面連到這裡，也沒有搜尋。

這個子專案把 `wiki/` **編譯成一個靜態網站**，目標是：

1. **好讀**：用網頁閱讀 wiki，連結可以點、表格有格式、矛盾與警示有醒目標示。
2. **好找**：依分類瀏覽、依標籤瀏覽、全文搜尋，並列出每頁的反向連結（哪些頁面引用了這頁）。
3. **零依賴**：只用 Python 標準函式庫建置，不需要安裝任何套件；產出的網站可以直接雙擊開啟（`file://`），也能放上 GitHub Pages。
4. **內容與呈現分離**：網站永遠由 `wiki/` 自動產生。**網站上看到的錯誤，要回去改 `wiki/` 的 Markdown，不是改 HTML。**

非目標：不做線上編輯、不做登入、不接資料庫、不在網頁端呼叫 LLM。

---

## 2. 使用方式

```bash
# 在專案根目錄執行（Windows 用 python，macOS/Linux 用 python3）
python web/build.py          # 讀 wiki/，輸出到 docs/
```

- 本機瀏覽：直接雙擊 `docs/index.html`。
- 線上瀏覽：推上 GitHub 後，在 repo 的 Settings → Pages 選 `main` 分支的 `/docs` 資料夾。
- **每次 ingest、lint 或手動修改 wiki 之後，都要重新執行 build**，並把 `docs/` 一起 commit。

## 3. 網頁風格

整體定位：**安靜、像研究筆記本的學術風格**。重點是長時間閱讀中文論文筆記不累，而不是炫目。

### 3.1 色彩（CSS 變數定義在 `web/static/style.css` 的 `:root`）

| 變數 | 淺色模式 | 深色模式 | 用途 |
|------|---------|---------|------|
| `--bg` | `#fbfaf7`（米白紙張） | `#16181d` | 頁面背景 |
| `--panel` | `#f3f1ea` | `#1e2128` | 側欄、資訊卡 |
| `--text` | `#1f2328` | `#e6e6e6` | 內文 |
| `--muted` | `#6b6f76` | `#9aa0a6` | 次要文字、日期 |
| `--accent` | `#2f4a7a`（墨藍） | `#8fb0e8` | 連結、標題線、按鈕 |
| `--warn` | `#b5452c`（朱紅） | `#e8826b` | ⚠️ 矛盾、待查證、斷鏈 |
| `--border` | `#e2ded3` | `#2c3038` | 分隔線 |

- 支援淺色與深色模式：預設跟隨系統，右上角按鈕可手動切換。
- 可信度徽章：`high` 綠、`medium` 黃、`low` 灰。

### 3.2 字體

- 內文：`"Noto Sans TC", "Microsoft JhengHei", "PingFang TC", system-ui, sans-serif`
- 標題：`"Noto Serif TC", "Songti TC", "PMingLiU", serif`（宋體，營造學術感）
- 程式碼：`ui-monospace, "Cascadia Code", Consolas, monospace`
- 內文 17px、行高 1.8，內容寬度最多 760px（中文一行約 40 字）。
- **不從 CDN 載入任何字體或函式庫**，網站離線也能正常顯示。

### 3.3 版面

- 桌機：左側固定側欄（站名、搜尋、分類），中間內容區，右側為本頁目錄（TOC）。
- 平板與手機（寬度 < 1000px）：右側目錄隱藏；寬度 < 760px 時側欄收合成「☰」選單。
- 不使用動畫、輪播、彈出視窗。

## 4. 頁面架構

```
docs/
├── index.html          首頁：總覽（wiki/overview.md）＋統計＋最近紀錄＋分類卡片
├── all.html            全部條目：渲染 wiki/index.md（含別名與一句話摘要）
├── tags.html           標籤頁：所有標籤與各自的頁面
├── log.html            紀錄頁：渲染 wiki/log.md，新的在上
├── c/<分類>.html        分類頁：該分類所有頁面，附摘要、更新日期、可信度
├── p/<頁面>.html        條目頁：每個 wiki 頁面一頁
└── assets/
    ├── style.css
    ├── app.js          主題切換、搜尋、手機選單
    └── search-index.js 建置時產生的搜尋索引
```

### 條目頁的組成（由上到下）

1. 麵包屑：首頁 › 分類 › 頁面
2. 標題
3. **資訊卡**：類型、可信度、最後更新、別名、標籤（可點）、來源（`raw/` 路徑）、arXiv 連結（若有）
4. 內文（Markdown 渲染結果）
5. **相關頁面**：來自 frontmatter `related`
6. **反向連結**：所有連到本頁的頁面（建置時自動計算）
7. 右側：本頁目錄（h2、h3）

### 特殊連結對應

| wiki 中的寫法 | 網站上連到 |
|--------------|-----------|
| `[[overview]]` | 首頁 |
| `[[index]]` | 全部條目 |
| `[[log]]` | 紀錄頁 |
| `[[頁面名稱]]`、`[[別名]]` | 該條目頁（不分大小寫，也可以用 `aliases` 中的別名） |
| `[[頁面名稱\|顯示文字]]` | 同上，顯示「顯示文字」 |
| 找不到的連結 | 以朱紅虛線顯示，滑鼠移上去提示「尚未建立」 |

## 5. 新增內容時要遵守的格式

網站完全依賴 `wiki/` 的格式。以下是建置程式**會讀取**的欄位，格式錯誤會讓網站顯示不完整：

### 5.1 Frontmatter（每個 wiki 頁面開頭）

```yaml
---
title: 頁面標題              # 必填，顯示為頁面標題
type: concept                # 必填，決定徽章；值見根目錄 AGENTS.md 第 6 節
aliases: [別名1, 別名2]       # 選填，搜尋與 [[連結]] 都會用到
created: 2026-11-17          # YYYY-MM-DD
last_updated: 2026-11-17     # YYYY-MM-DD，分類頁依此排序
tags: [標籤1, 標籤2]          # 選填，產生標籤頁
related: ["[[頁面A]]", "[[頁面B]]"]   # 選填，含 [[ ]] 的字串要加引號
sources: ["raw/papers/檔名.pdf"]      # 選填
confidence: high | medium | low      # 選填，產生可信度徽章
arxiv: "2203.02155"          # 選填，論文頁會產生 arXiv 連結
---
```

- 只支援「一行一個欄位」的簡單 YAML。清單一律寫成 `[a, b, c]` 的單行格式，**不要**用多行的 `- a` 清單。
- 含有逗號或 `[[ ]]` 的清單項目要用雙引號包起來。

### 5.2 內文支援的 Markdown

標題 `#`～`######`、段落、粗體、斜體、行內程式碼、程式碼區塊、引用 `>`、項目清單與編號清單（可縮排兩格做巢狀）、核取方塊 `- [ ]`、表格、水平線 `---`、一般連結、圖片、`[[wikilink]]`。

**特殊標記（網站會套用醒目樣式）：**

| 寫法 | 呈現 |
|------|------|
| `> ⚠️ 矛盾：……` 或 `> ⚠️ 待查證：……` | 朱紅色警示框 |
| `> 💡 ……` | 墨藍色提示框 |
| 其他 `> ……` | 一般引用 |
| 文中的「（我的推測）」 | 自動以斜體淡色標示 |

不支援：HTML 標籤（會被當成純文字顯示，以確保安全）、註腳、數學公式、Mermaid（列入第 8 節待辦）。

### 5.3 一句話摘要

分類頁與首頁卡片上的摘要，取自 `wiki/index.md` 中該頁那一行冒號後面的文字。**新增頁面時一定要更新 index.md**，否則網站會改用內文第一段當摘要。

## 6. 檔案命名與放置

| 東西 | 放哪裡 | 命名規則 |
|------|-------|---------|
| wiki 內容 | `wiki/<分類>/` | 依根目錄 AGENTS.md：檔名＝頁面標題 |
| 建置程式 | `web/build.py`、`web/md.py` | 不新增其他 Python 檔，除非真的需要拆分 |
| 樣式與前端程式 | `web/static/` | `style.css`、`app.js`，原始檔只放這裡 |
| 產出的網站 | `docs/` | **由程式產生，禁止手動修改** |
| 本規格書 | `web/AGENTS.md`、`web/CLAUDE.md` | |

**網址規則（由 build.py 自動處理，人不用手動做）：**
- 條目頁：`docs/p/<檔名>.html`，空白換成 `-`，其餘字元（含中文）保留。例：`STT-LLM-TTS Pipeline.md` → `p/STT-LLM-TTS-Pipeline.html`。
- 分類頁：`docs/c/<資料夾名稱>.html`。
- 兩個頁面轉換後的檔名相同時，建置會報錯並停止，必須改其中一頁的檔名。
- 新增分類資料夾（例如 `wiki/tools/`）時，在 `build.py` 的 `CATEGORY_LABELS` 加上中文名稱；沒加的話直接顯示英文資料夾名稱。

## 7. AI 修改或新增時要遵守的規則

### 7.1 改內容 vs. 改網站

- **內容錯了**（錯字、事實、連結）→ 改 `wiki/` 的 Markdown，再重新 build。**絕不直接改 `docs/`。**
- **呈現錯了**（排版、樣式、功能）→ 改 `web/`，再重新 build。
- 任何修改都要讓 `python web/build.py` 能在沒有安裝任何套件的情況下執行成功。

### 7.2 開發規則

1. **只用 Python 標準函式庫**，前端只用原生 HTML、CSS、JavaScript。不引入 npm、框架或 CDN。
2. **所有路徑都用相對路徑**，網站必須能用 `file://` 直接開啟，也能在 GitHub Pages 的子路徑下運作。
3. **安全**：Markdown 裡的文字一律做 HTML escape；不執行內容中的 HTML 或 script。
4. **可及性**：連結要有可辨識的文字；顏色對比至少符合 WCAG AA；搜尋框要有 label；可以只用鍵盤操作（`/` 聚焦搜尋）。
5. **樣式集中**：顏色只用 `:root` 的 CSS 變數，不在其他地方寫死色碼。
6. **localStorage 只用來記住深淺色模式**，讀寫一律包在 try/catch 裡。
7. 修改 `md.py` 的 Markdown 解析時，必須確認現有所有 wiki 頁面重新 build 後顯示正常，不能只測新功能。

### 7.3 每次修改後的檢查流程

1. 執行 `python web/build.py`，確認沒有錯誤；終端機會列出斷鏈，斷鏈要回報。
2. 打開 `docs/index.html`，至少檢查：首頁、一個分類頁、一個內容最多的條目頁、搜尋功能、深色模式、手機寬度。
3. 在根目錄 `wiki/log.md` 追加一筆紀錄，例如 `## [YYYY-MM-DD] web | 新增標籤頁`。
4. commit 時把 `web/` 與 `docs/` 的修改一起提交。

### 7.4 不要做的事

- 不要為了網站好看而修改 `wiki/` 頁面的內容或結構。網站要配合 wiki 的格式，不是反過來。
- 不要刪除 `docs/` 以外的任何檔案。
- 不要把 `raw/` 裡的 PDF 原文發布到網站上（版權與隱私考量，`.gitignore` 已排除 PDF）。

## 8. 後續發展（依優先順序）

接手的 agent 請從上往下挑選，完成後把該項打勾並在 log 記錄：

- [x] v1：首頁、分類頁、條目頁、標籤頁、紀錄頁、全文搜尋、反向連結、深色模式、手機版面
- [ ] 建置時順便執行 `tools/lint.py` 的檢查，並在首頁顯示「健康狀態」（斷鏈、孤兒頁數量）
- [ ] 關聯圖（Graph view）：用原生 SVG 或 Canvas 畫出頁面之間的連結，點擊節點跳到該頁
- [ ] 論文頁的「主要結果」表格支援排序
- [ ] 支援 Mermaid 圖（需要離線可用的方案，不得使用 CDN）
- [ ] GitHub Actions：push 到 main 時自動執行 build 並部署 Pages，不必再手動 commit `docs/`
- [ ] 時間線頁：整合所有頁面的「時間線」表格
