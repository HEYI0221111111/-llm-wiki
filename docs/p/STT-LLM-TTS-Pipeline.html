    STT-LLM-TTS Pipeline

    方法可信度中建立 2026-11-17 · 更新 2026-11-17
    別名語音對話管線、voice agent pipeline、串接式語音代理、cascaded voice agent、Whisper GPT TTS
    標籤voice agent 系統架構 Unity LLM 應用
    來源raw/papers/以人工智慧支援之協作式虛擬實境提升實用英語溝通能力.pdf

    把「語音轉文字（STT）、大型語言模型（LLM）、文字轉語音（TTS）」三個模組串起來，讓使用者能用語音和 LLM 即時對話。這是目前 VR、虛擬人和語言學習系統中最常見的語音代理做法。

    解決什麼問題

    文字型 LLM 不能直接聽、說。串接三個現成模組，不需要訓練端到端的語音模型，就能做出可對話的虛擬角色，而且每個模組都可以單獨替換。

    典型做法（以一個 Unity VR 實作為例）

    依 以人工智慧支援之協作式虛擬實境提升實用英語溝通能力 的架構：

    1. 擷取：Unity 用戶端錄下麥克風聲音，壓縮後以 HTTP POST 傳給 Python 後端。
    2. STT：Whisper（base.en）轉成文字，再做簡單的清理與斷句。
    3. LLM：GPT-3.5 Turbo 依情境 prompt 與對話歷史生成回應，並依學習者程度調整用字難度。
    4. TTS：Edge-TTS 把回應合成成語音。
    5. 回傳與記錄：語音傳回 Unity，以 3D 空間音效播放。文字與後設資料（角色、npc_id、時間戳）存入 SQLite。
    6. 脈絡維持：每次請求都從資料庫取出該 NPC 的對話歷史，一起送給 LLM。

    多人版本可以讓所有使用者共用同一份對話歷史，再以 RPC 把 AI 語音同時廣播給每位使用者。

    設計上的取捨

    選擇好處代價
    前後端分離（Unity 加 Python 後端）運算集中、可支援多位使用者、模組可替換多一段網路延遲
    小型 STT 模型（Whisper base.en）快、資源需求低非母語口音與噪音下的辨識錯誤較多
    雲端 LLM對話品質高延遲與網路穩定性會影響輪流發言
    只播語音、不顯示字幕強迫練聽力辨識錯誤時，使用者難以判斷是誰的問題

    已知問題

    • 延遲與辨識錯誤是使用者最常反映的問題，會打斷輪流發言。該研究的受試者有時無法分辨溝通失敗是自己的問題還是系統的問題，不過多數人把它歸因於技術限制（來源：以人工智慧支援之協作式虛擬實境提升實用英語溝通能力）。
    • 原作者建議的改進方向：使用更大的 STT 模型、改善網路，以及雲端與本地模型可切換的混合架構。
    • AI NPC 若沒有唇形同步，非語言線索會比真人 avatar 少。
